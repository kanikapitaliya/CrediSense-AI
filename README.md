# 🛡️ CrediSense AI - Credit Risk Intelligence Platform

**CrediSense AI** is an enterprise-grade AI platform for credit risk scoring, explainability, automated policy rules evaluation, and natural language data querying (**Talk-to-Data**) powered by Google Gemini LLM and LightGBM.

---

## 📌 Executive Feature Overview

1. **📊 Exploratory Data Analysis & Business Insights**: Empirical analytics on 307,511 credit applicants.
2. **🎯 Real-Time Credit Default Scoring**: Out-of-fold LightGBM probability scoring with class imbalance handling (`scale_pos_weight = 11.38`).
3. **💡 Explainable AI (SHAP Waterfall & Plain-Language Translation)**: Feature attribution waterfall charts and non-technical executive risk breakdowns.
4. **⚖️ Decision Rules Engine**: Automated evaluation of empirical policy rules (e.g. debt-to-income caps, overdue credit escalation).
5. **💬 Talk-to-Data (Gemini LLM NL-to-SQL Engine)**: Conversational natural language query engine backed by Google Gemini LLM, SQLite database, strict security validation, and conversation memory.
6. **🐳 Docker Containerization**: Zero-config containerized deployment via `docker compose`.

---

## 🤖 Talk-to-Data (NL-to-SQL) Architecture

```
User Question + Conversation Memory (Session State)
                   │
                   ▼
       Google Gemini LLM (gemini-2.5-flash)
                   │
                   ▼
         Generated SQLite Query
                   │
                   ▼
     SQL Security & Schema Validator
       (Read-Only SELECT / WITH Enforced)
                   │
                   ▼
          SQLite Database Execution
                   │
                   ▼
     Returned Data (Pandas DataFrame)
                   │
                   ▼
    Gemini Grounded Business Summarization
                   │
                   ▼
  Interactive Streamlit Intelligence Platform UI
```

## 🛠️ Gemini Provider & Model Selection

- **Provider**: Official Google GenAI SDK (`google-genai`)
- **Default Model**: `gemini-2.5-flash` (configurable via `GEMINI_MODEL` environment variable)
- **Why Selected**:
  - High accuracy in structured text translation (SQL generation).
  - Extremely fast response times (< 1 second generation latency).
  - Cost-efficient token utilization suitable for real-time enterprise query tools.

## 🐳 Docker Deployment Instructions

### 1. Create Environment File
Copy `.env.example` to `.env` and add your Gemini API Key:
```bash
cp .env.example .env
```
Edit `.env`:
```env
GEMINI_API_KEY=your_actual_gemini_api_key_here
GEMINI_MODEL=gemini-2.5-flash
```

### 2. Build and Start Container
Run the application using Docker Compose:
```bash
docker compose up --build
```
> The container automatically mounts `./datasets` (read-only), `./data`, and `./models/saved_models` so the SQLite database index and pre-trained LightGBM models are available instantly without regenerating expensive artifacts.

### 3. Access Application
Open your web browser at:
**`http://localhost:8501`**

### 4. Stop Container
To stop the running Docker application:
```bash
docker compose down
```

## 🧠 Prompt Design & Token Optimization

- **Schema Definition**: Concise, token-optimized schema representation of SQLite tables (`applications`, `bureau_summary`, `previous_applications_summary`) included in system prompt ([nl2sql/prompts.py](file:///d:/Projects/CrediSense-AI/nl2sql/prompts.py)).
- **Token Control**:
  - Full CSV datasets are **never** sent to Gemini.
  - Conversation context is truncated to the **last 3 turns**.
  - Returned data previews are truncated to top 15 records.

---

## 🛡️ SQL Validation & Security Rules

All queries generated by Gemini or entered by users must pass strict security checks ([nl2sql/validator.py](file:///d:/Projects/CrediSense-AI/nl2sql/validator.py)):

1. **Read-Only Command Enforced**: Must begin with `SELECT`, `WITH`, or `EXPLAIN`.
2. **Forbidden Destructive Keywords**: Immediately rejects queries containing `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `TRUNCATE`, `CREATE`, `RENAME`, `REPLACE`, `GRANT`, `REVOKE`, `EXEC`, `EXECUTE`.
3. **Multi-Statement Injection Prevention**: Rejects queries with semicolons `;` in statement body.
4. **Schema Table Verification**: Ensures referenced tables exist in `ALLOWED_TABLES` (`applications`, `bureau_summary`, `previous_applications_summary`).

---

## 🚫 Anti-Hallucination & Grounding Safeguards

1. **Execution-First Grounding**: Gemini is never allowed to directly invent figures. Numerical answers are generated strictly from the returned SQLite DataFrame.
2. **Second-Pass Summarization**: A second concise Gemini call summarizes the DataFrame into natural language using ONLY the question, SQL, and query result.
3. **Graceful Fallback**: If Gemini fails, times out, or produces invalid SQL, the engine falls back to deterministic pre-validated SQL patterns and clearly labels the execution mode.

---

## 💬 Conversation Memory

- Uses Streamlit `session_state['talk_to_data_history']` to store recent interaction turns.
- Preserves context across follow-up questions (e.g. *"What is the default rate by education?"* followed by *"Which group has the highest rate?"*).
- Limits context window to 3-5 turns to maintain token efficiency and prevent prompt pollution.

## 📋 6 Core Business Query Patterns & Examples

The engine supports dynamic Gemini translations and pre-validated fallback patterns for key credit analytics questions:

| # | Query Pattern Category | Example User Question | Validated SQL Query |
| :--- | :--- | :--- | :--- |
| 1 | **Education Level** | *"What is the default rate by education level?"* | `SELECT NAME_EDUCATION_TYPE, COUNT(*) as applicant_count, ROUND(AVG(TARGET)*100, 2) as default_rate_pct, ROUND(AVG(AMT_INCOME_TOTAL), 2) as avg_income FROM applications GROUP BY NAME_EDUCATION_TYPE ORDER BY default_rate_pct DESC` |
| 2 | **Contract Type** | *"Show average credit amount and annuity by contract type"* | `SELECT NAME_CONTRACT_TYPE, COUNT(*) as applicant_count, ROUND(AVG(AMT_CREDIT), 2) as avg_credit_amount, ROUND(AVG(AMT_ANNUITY), 2) as avg_annuity, ROUND(AVG(TARGET)*100, 2) as default_rate_pct FROM applications GROUP BY NAME_CONTRACT_TYPE` |
| 3 | **Bureau History** | *"What are default rates for applicants with active bureau loans?"* | `SELECT b.active_loans, COUNT(*) as applicant_count, ROUND(AVG(a.TARGET)*100, 2) as default_rate_pct FROM applications a JOIN bureau_summary b ON a.SK_ID_CURR = b.SK_ID_CURR GROUP BY b.active_loans HAVING applicant_count > 100 ORDER BY b.active_loans LIMIT 10` |
| 4 | **Income Category** | *"Compare default statistics across income types"* | `SELECT NAME_INCOME_TYPE, COUNT(*) as count, ROUND(AVG(TARGET)*100, 2) as default_rate_pct, ROUND(AVG(AMT_INCOME_TOTAL), 2) as avg_income FROM applications GROUP BY NAME_INCOME_TYPE HAVING count > 50 ORDER BY default_rate_pct DESC` |
| 5 | **Prior Applications** | *"Previous application refusal vs approval stats by education"* | `SELECT a.NAME_EDUCATION_TYPE, SUM(p.approved_count) as total_approved, SUM(p.refused_count) as total_refused, ROUND(CAST(SUM(p.refused_count) AS FLOAT) / (SUM(p.approved_count) + SUM(p.refused_count) + 1e-5)*100, 2) as refusal_rate_pct FROM applications a JOIN previous_applications_summary p ON a.SK_ID_CURR = p.SK_ID_CURR GROUP BY a.NAME_EDUCATION_TYPE ORDER BY refusal_rate_pct DESC` |
| 6 | **High Exposure** | *"List top 10 applicants with highest requested credit amount"* | `SELECT SK_ID_CURR, TARGET_LABEL, NAME_CONTRACT_TYPE, AMT_CREDIT, AMT_INCOME_TOTAL, AGE_YEARS, EXT_SOURCE_MEAN FROM applications ORDER BY AMT_CREDIT DESC LIMIT 10` |

- Database initial size is populated from 50,000 application rows for optimal SQLite local latency.
